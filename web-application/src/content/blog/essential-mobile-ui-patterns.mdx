# 10 UI Patterns Every Mobile Developer Should Know

Creating intuitive mobile experiences requires more than just good code – it requires understanding the UI patterns that users expect and love. Here are 10 essential patterns that every mobile developer should master.

## 1. Pull-to-Refresh

**When to Use**: Lists, feeds, and data that changes frequently

The pull-to-refresh pattern gives users control over data freshness while providing satisfying haptic feedback.

```typescript
const FeedScreen = () => {
  const [refreshing, setRefreshing] = useState(false);
  const [data, setData] = useState([]);

  const onRefresh = async () => {
    setRefreshing(true);
    try {
      const newData = await fetchLatestPosts();
      setData(newData);
    } finally {
      setRefreshing(false);
    }
  };

  return (
    <FlatList
      data={data}
      refreshControl={
        <RefreshControl refreshing={refreshing} onRefresh={onRefresh} />
      }
      renderItem={({ item }) => <PostCard post={item} />}
    />
  );
};
```

<Callout type="tip">
Always provide visual feedback during the refresh process and consider adding a subtle animation to make the interaction feel responsive.
</Callout>

## 2. Infinite Scroll

**When to Use**: Large datasets, social feeds, search results

Infinite scroll eliminates pagination and creates seamless browsing experiences.

```typescript
const InfiniteScrollList = () => {
  const [data, setData] = useState([]);
  const [loading, setLoading] = useState(false);
  const [hasMore, setHasMore] = useState(true);
  const [page, setPage] = useState(1);

  const loadMore = async () => {
    if (loading || !hasMore) return;
    
    setLoading(true);
    const newData = await fetchData(page);
    
    if (newData.length === 0) {
      setHasMore(false);
    } else {
      setData(prev => [...prev, ...newData]);
      setPage(prev => prev + 1);
    }
    setLoading(false);
  };

  return (
    <FlatList
      data={data}
      onEndReached={loadMore}
      onEndReachedThreshold={0.5}
      ListFooterComponent={loading ? <LoadingSpinner /> : null}
    />
  );
};
```

## 3. Empty States

**When to Use**: When lists, searches, or features have no content

Empty states guide users and provide next steps instead of showing blank screens.

| Empty State Type | Message Strategy | Action Button |
|------------------|------------------|---------------|
| First Use | Explain the feature's value | "Get Started" |
| No Search Results | Suggest alternatives | "Clear Filters" |
| Network Error | Explain the problem | "Try Again" |
| User Generated Content | Encourage creation | "Add Your First Item" |

```typescript
const EmptyState = ({ type, onAction }) => {
  const configs = {
    noResults: {
      icon: "🔍",
      title: "No results found",
      message: "Try adjusting your search or filters",
      action: "Clear Filters"
    },
    firstUse: {
      icon: "🎉",
      title: "Welcome to your dashboard",
      message: "Create your first project to get started",
      action: "Create Project"
    }
  };

  const config = configs[type];

  return (
    <View style={styles.emptyState}>
      <Text style={styles.icon}>{config.icon}</Text>
      <Text style={styles.title}>{config.title}</Text>
      <Text style={styles.message}>{config.message}</Text>
      <Button onPress={onAction}>{config.action}</Button>
    </View>
  );
};
```

## 4. Swipe Actions

**When to Use**: List items with contextual actions (delete, archive, favorite)

Swipe actions provide quick access to common functions without cluttering the interface.

<Callout type="warning">
Always provide clear visual cues for swipe actions and consider adding haptic feedback to make the interaction feel natural.
</Callout>

## 5. Progressive Disclosure

**When to Use**: Complex forms, settings, or detailed information

Show information progressively to avoid overwhelming users while maintaining access to advanced features.

```typescript
const AdvancedSettings = () => {
  const [showAdvanced, setShowAdvanced] = useState(false);

  return (
    <View>
      {/* Basic settings always visible */}
      <Setting label="Notifications" />
      <Setting label="Dark Mode" />
      
      {/* Advanced settings behind disclosure */}
      <TouchableOpacity 
        onPress={() => setShowAdvanced(!showAdvanced)}
        style={styles.disclosureButton}
      >
        <Text>Advanced Settings</Text>
        <Icon name={showAdvanced ? "chevron-up" : "chevron-down"} />
      </TouchableOpacity>
      
      {showAdvanced && (
        <View style={styles.advancedSection}>
          <Setting label="Debug Mode" />
          <Setting label="Cache Size" />
          <Setting label="API Timeout" />
        </View>
      )}
    </View>
  );
};
```

## 6. Loading States

**When to Use**: Any operation that takes more than 100ms

Good loading states manage user expectations and reduce perceived wait time.

### Loading State Types

**Skeleton Loading**: Shows the structure while content loads
```typescript
const SkeletonLoader = () => (
  <View style={styles.skeleton}>
    <View style={[styles.line, styles.title]} />
    <View style={[styles.line, styles.subtitle]} />
    <View style={[styles.line, styles.content]} />
  </View>
);
```

**Progressive Loading**: Shows content as it becomes available
```typescript
const ProgressivePost = ({ post }) => (
  <View>
    <Text>{post.title}</Text>
    {post.excerpt && <Text>{post.excerpt}</Text>}
    {post.content ? (
      <Text>{post.content}</Text>
    ) : (
      <LoadingSpinner />
    )}
  </View>
);
```

## 7. Form Validation

**When to Use**: Any user input forms

Provide immediate, helpful feedback to guide users toward successful form completion.

```typescript
const ValidatedInput = ({ value, onChange, rules, label }) => {
  const [error, setError] = useState('');
  const [touched, setTouched] = useState(false);

  const validate = (inputValue) => {
    for (const rule of rules) {
      const result = rule(inputValue);
      if (!result.valid) {
        setError(result.message);
        return false;
      }
    }
    setError('');
    return true;
  };

  return (
    <View style={styles.inputGroup}>
      <Text style={styles.label}>{label}</Text>
      <TextInput
        value={value}
        onChangeText={(text) => {
          onChange(text);
          if (touched) validate(text);
        }}
        onBlur={() => {
          setTouched(true);
          validate(value);
        }}
        style={[styles.input, error ? styles.inputError : null]}
      />
      {error && touched && (
        <Text style={styles.errorText}>{error}</Text>
      )}
    </View>
  );
};
```

<Callout type="success">
Validate inputs in real-time after the user first interacts with a field, but avoid showing errors before they've had a chance to complete their input.
</Callout>

## 8. Onboarding Flow

**When to Use**: First-time user experience for complex apps

Guide new users to their first success moment quickly and efficiently.

### Effective Onboarding Principles

1. **Show, Don't Tell**: Use interactive tutorials over static instructions
2. **Focus on Value**: Highlight benefits, not features  
3. **Progressive Engagement**: Start simple, add complexity gradually
4. **Allow Skipping**: Let experienced users bypass introductions

```typescript
const OnboardingFlow = () => {
  const [currentStep, setCurrentStep] = useState(0);
  
  const steps = [
    {
      title: "Welcome to TaskMaster",
      description: "Organize your life, one task at a time",
      component: <WelcomeScreen />
    },
    {
      title: "Create Your First Task",
      description: "Let's start with something simple",
      component: <InteractiveTaskCreation />
    },
    {
      title: "You're All Set!",
      description: "Ready to boost your productivity?",
      component: <CompletionScreen />
    }
  ];

  return (
    <View style={styles.onboarding}>
      {steps[currentStep].component}
      <View style={styles.navigation}>
        <ProgressIndicator 
          current={currentStep} 
          total={steps.length} 
        />
        <Button 
          onPress={() => setCurrentStep(currentStep + 1)}
          disabled={currentStep === steps.length - 1}
        >
          {currentStep === steps.length - 1 ? "Get Started" : "Next"}
        </Button>
      </View>
    </View>
  );
};
```

## 9. Tab Bar Navigation

**When to Use**: 3-5 primary sections of equal importance

Tab bars provide quick access to top-level views and show users where they are in the app hierarchy.

### Tab Bar Best Practices

- **Use 3-5 tabs maximum** (iOS HIG recommendation)
- **Include meaningful icons** with short labels
- **Maintain consistent tab order** across app updates
- **Highlight the active tab** clearly

## 10. Modal Hierarchy

**When to Use**: Focused tasks, confirmations, or contextual information

Modals create focused experiences but should be used judiciously to avoid breaking user flow.

```typescript
const ModalManager = () => {
  const [modalStack, setModalStack] = useState([]);

  const openModal = (modalComponent, options = {}) => {
    setModalStack(prev => [...prev, { 
      component: modalComponent, 
      options,
      id: Date.now() 
    }]);
  };

  const closeModal = (id) => {
    setModalStack(prev => prev.filter(modal => modal.id !== id));
  };

  return (
    <>
      {modalStack.map(modal => (
        <Modal
          key={modal.id}
          visible={true}
          animationType={modal.options.animationType || "slide"}
          presentationStyle={modal.options.presentationStyle || "pageSheet"}
        >
          <modal.component onClose={() => closeModal(modal.id)} />
        </Modal>
      ))}
    </>
  );
};
```

## Implementation Tips

### Performance Considerations

- **Use FlatList** for long lists instead of ScrollView
- **Implement lazy loading** for heavy content
- **Optimize images** with appropriate sizes and formats
- **Use React.memo** for components that re-render frequently

### Accessibility

- **Add semantic labels** to all interactive elements
- **Ensure sufficient color contrast** (WCAG 2.1 AA standard)
- **Support voice navigation** with proper heading structure
- **Test with screen readers** regularly

### Platform Consistency

While maintaining your brand identity, respect platform conventions:

| Pattern | iOS Standard | Android Standard |
|---------|--------------|------------------|
| Navigation | Tab bar at bottom | Navigation drawer or bottom navigation |
| Back Action | Top-left arrow | Hardware/software back button |
| Search | Pull down to reveal | Dedicated search bar or FAB |
| Settings | Gear icon, right-aligned | Three dots menu (overflow) |

## Conclusion

Mastering these UI patterns isn't just about following conventions – it's about creating experiences that feel natural and intuitive to your users. The best mobile apps combine these patterns thoughtfully, adapting them to their specific use cases while maintaining the core usability principles that make them effective.

Remember: **Good UI patterns are invisible to users but essential for great user experiences.**

Start implementing these patterns in your next project, and you'll notice immediate improvements in user engagement and satisfaction.
